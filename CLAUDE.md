# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Spaceport Iridium is a 2D Godot 4.7 (GDScript) game: a cross between SimTower (build a space station one module at a time, viewed as a side-on vertical cross-section) and Dwarf Fortress/RimWorld (manage a population of pawns, fulfill their needs, keep them happy). Station residents move between modules via corridors/turbolifts and go outside through airlocks to mine asteroids or construct modules.

## Planning documents

`Obsidian Vault/Spaceport Iridium/Planning/` holds the authoritative plans: design doc, `01_Technical_Specification.md` (current architecture, kept up to date through WI-40), roadmap, `03_Bugs_and_Improvements.md` (known issues), and per-task implementation docs in `Work Items/`. Check the relevant WI doc before starting feature work — several record deviations from their own design in a status block at the top, and those deviations are what actually shipped. The rest of the Obsidian Vault is raw design notes.

## Running & verifying

- No build step, no test framework beyond GUT, no linter beyond the editor. Typed-GDScript warnings (`untyped_declaration`, `unsafe_property_access`, `unsafe_method_access`) are enabled in project.godot — keep everything typed.
- **The boot scene is `ui/menus/main_menu.tscn`, not `main.tscn` (WI-36).** `godot --path .` opens the main menu; New Game stages a `DifficultyData` on `Global` and Load stages a save on `SaveManager` *before* swapping to `main.tscn`. Playing `main.tscn` directly from the editor still works — difficulty falls back to Normal and no save is pending. Export preset: `"Windows Desktop"`.
- The godot-ai MCP plugin is installed. Typical verify loop: `project_run` → `logs_read(source="game")` / `logs_read(source="editor")` → `game_manage` (inspect nodes, read UI text, send input) → `project_manage(op="stop")`.
  - After creating a **new file with a `class_name`**, run `filesystem_manage(op="scan")` before `project_run`, or the class won't resolve ("Could not find type X in the current scope"). The editor's global class cache also goes stale on its own — `godot --headless --import` recovers it.
  - **MCP has been unreliable through the back half of Phase 3.** The fallback that works: a temporary autoload "probe" script that runs a numbered checklist headlessly and prints pass/fail per check, then gets deleted. WI-30 through WI-33 were all verified that way. What headless genuinely cannot verify is `_draw()` output and shader behavior (the minimap and overlays).
- **Unit tests (GUT, WI-19):** GUT is vendored at `addons/gut/`; pure-logic suites live in `tests/unit/` (32 suites, 377 tests). Run headless:
  ```
  godot --headless -s addons/gut/gut_cmdln.gd -gdir=res://tests/unit -gexit
  ```
  (exits 0 all-green, non-zero on any failure). If new `class_name` files were added since the last editor open, run `godot --headless --import` once first. Tests cover **pure classes only** — construct them directly, never touch `Global`/`SignalBus`. Current coverage: `ModuleGraph`, `StorageData`, `StatModifiers`, `LocalUpgradeData` cost scaling, `MarketManager` pricing, contract/event rules, skill curves, hire pricing, damage→efficiency, economy, station tiers, workspaces, robot energy/integrity, food quality, adjacency, disease, raid targeting, shield math + capacitor persistence, shops, visitors, `MinimapTransform`, `OverlayPalette`, save slots, `GameSettings`, difficulty, job serialization. Keep test code fully typed; `tests/` and `addons/gut/` are excluded from the export preset.
- **Cheat console (Panku, WI-19):** the backtick key opens Panku's REPL in-game; `Global.cheats.<method>(...)` drives `Cheats` (`scripts/utility/cheats.gd`). Roughly 30 methods now — build/damage/repair/break a module, `spawn_resource`, `spawn_pawn`, `set_skill`/`add_trait`, `infect`/`cure`, `add_credits`/`set_credits`, `set_economy_costs`/`take_loan`, `tier_up`/`grant_export`/`start_inspection`, `force_unlock`/`unlock_all`, `set_time_speed`/`advance_hours`, `start_raid`/`pay_raid`, `spawn_visitor`/`set_reputation`, `show_difficulty`/`set_difficulty`, `fire_event`, `offer_contract`, `dump_adjacency`. Every call emits a `station_alert` "CHEAT: …" so a save that used them is self-documenting. **Pass ids as plain strings, not `&"…"`** — Godot's `Expression` (what the REPL runs) rejects StringName literals but coerces `String`→`StringName` on the call, e.g. `Global.cheats.spawn_resource("iron_ore", 50, Vector2i(16,8))`.

## Architecture

Composition over inheritance, uniformly. New features = new component + new `JobBase` subclass + new `.tres` data, not new class hierarchies. `01_Technical_Specification.md` is the full picture; what follows is the load-bearing summary.

**Managers** — `Global` and `SignalBus` are the only autoloads (plus `Panku`). Every other manager is a node in `main.tscn` under `Managers/` that registers itself into `Global.<name>` in `_ready()`: TimeManager, WorldManager, PathManager, AtmosphereManager, StructureManager, AdjacencyManager, PowerManager, TurboliftManager, JobManager, ResourceManager, MarketManager, EconomyManager, AsteroidManager, AudioManager, UnlockManager, CrewManager, TraderManager, EventManager, ContractManager, RaidManager, VisitorManager, SaveManager. **Tree order = ready order and it is load-bearing:** `TimeManager` first (everything subscribes to its signals in `_ready`), `SaveManager` last (it applies a pending load deferred). Cross-system events go through `SignalBus` typed signals (~45 of them).

**Modules** — a module is a scene rooted in `ModuleBase` (`modules/templates/module_base.gd`) composed of child components (`modules/components/`): storage, processor, construction, path, structure, power gen/consumption, battery, mining, sustenance, sleep, recreation providers (social/entertainment/shop), trade, atmosphere, workspace, conveyor, logistics bay, recharge, robot repair, medical, adjacency emitter, weapon, shield, etc. Module *identity* is a `ModuleData` resource (`data/modules/**/*.tres`) carrying costs, tags, layers, and the scene reference. The build menu, unlock trees, and local upgrades are discovered by scanning `data/` directories via `ResourceScanner` (handles exported-build `.remap` suffixes — don't hand-roll directory scans).

**Pawns** — `PawnBase` + `PawnComponentBase` children (movement, inventory, needs, health, breathing, skills, traits, disease, socialize). Three specializations differ by *which components they carry and where they source jobs*, not by behavior overrides: `RobotPawnBase` (drones, haulers — no needs/schedule/skills, plus energy + integrity components created in code), `VisitorPawn` (needs and disease, no schedule/skills/traits, `is_visitor`), `InspectorPawn` (runtime-only, the one pawn excluded from saves).

**Grid & layers** — `WorldManager` tracks cell→module maps per `StructureLayer` (MODULE, CORRIDOR, TURBOLIFT, SPACE); one cell can hold a module, a corridor, and a turbolift simultaneously. Truss is a placeholder module auto-placed when a real module is removed. Module lifecycle is Preview → Blueprint (construction site) → Built; components implement `ready_preview/ready_blueprint/ready_constructed`.

**Pathfinding & movement** — two separate `ModuleGraph`s: `PathManager` (pawn traversal) and `StructureManager` (physical attachment, and the substrate adjacency fields propagate over). The graph supports vertex *groups* (e.g. `"turboshaft_N"`) whose members are implicitly interconnected with a per-group cost multiplier, an `is_exterior` flag (separate from groups since WI-15), plus subgraph ids for O(1) `is_reachable` checks — jobs rely on that being cheap. Within a module, `PathComponent` holds an interior `AStar2D` micro-graph, doors mapped to layers, authored/generated **anchors** (bunks, workstations, charger pads — each with an optional animation), and `PathBehavior` strategy objects. Anything that **owns a pawn's position** (turbolift rides) is an explicit serializable `CONVEYED` movement state, not a suspended `await`; `exit_conveyed()` re-runs pathfinding from the drop-off floor rather than resuming a path index, so normal arrival, diverted drop-offs, and ejection are one mechanism. Awaits remain only for cosmetic waits (door animations).

**Jobs & hauling** — modules post `JobBase` subclasses (`scripts/jobs/`) to `JobManager`'s priority-sorted board; pawns claim and drive them as state machines via `process_job(delta)`. `StorageComponent` posts pull/push jobs from desired-amount deficits/surpluses; **storage priority is the routing language** (construction imports at +99, deconstruction exports at −99, sinks must out-priority sources). Every "which bin?" decision goes through `StorageQuery.find_source()` / `find_sink()` (`scripts/utility/storage_query.gd`, WI-40) — pure, group-scan-based, with the strict directional priority filter and the deliberate no-filter case (piles, cargo sweeps) documented there and nowhere else. `JobBase.workspace` gates a module's work jobs to its assigned crew and gives assignees a priority-affinity bonus (WI-23) — sized to win ties, never to cross the routing bands. Followup jobs and queued needs go through the pawn's personal `job_queue`, never the board. Resource stacks (`ResourceStack` + optional `ItemInstanceData` — ore richness, food quality) move physically: storage → pawn inventory → storage, with reservations on both ends.

**Time** — `TimeManager` owns game time (cycles/hours, `SECONDS_PER_HOUR`), pause, and speed. Rules: per-frame gameplay `_process` handlers multiply delta by `Global.time_manager.scale(delta)` and early-return on 0; periodic scans subscribe to `slow_tick`; calendar behavior uses `hour_changed`/`cycle_changed`; one-shot waits use `await Global.time_manager.sim_seconds(x)`, never `get_tree().create_timer()`. Gameplay animations follow sim speed via `animation_speed()` + the `sim_animation` group (pawn sprites re-apply per frame instead — they reparent constantly). Never use `Engine.time_scale` or `get_tree().paused` — UI stays real-time.

**Unlocks, tiers & difficulty** — `UnlockManager` holds global tech-tree state (`UnlockData` .tres + `UnlockEffect`s), per-module `LocalUpgradeData`, **and** the 1–5 `TierData` ladder (export goals + a walking ARC inspector gate unlock `min_tier`s; the first passed inspection switches `EconomyManager`'s cost streams on). Both modifier sources feed a `StatModifiers` layer per module instance, and components read tunable stats through `owner_module.get_effective_stat(&"stat", base)` so upgrades apply non-destructively. Damage, breakdowns, and adjacency each push through their own **named** modifier source so they stack and clear independently. Difficulty (`DifficultyData`, WI-37) is staged on `Global` before the scene swap and never changes mid-run; read it through `Global.difficulty_*()` helpers.

**Atmosphere, adjacency, combat** — `AtmosphereManager` runtime-attaches `AtmosphereComponent` to eligible modules (one eligibility rule in one place; new modules need no wiring) and diffuses gas over path-graph door edges on `slow_tick`, mass-conservingly. `AdjacencyManager` propagates named effect fields (`vibration`, `greenery`, `maintenance`, `purified_air`) over the *structure* graph with per-hop falloff — change-driven and coalesced, never a tick scan, never saved. `RaidManager` owns pirate waves, routes every hit through `ShieldMath` to the best covering bubble, and restores a whole in-progress fight from its save section.

**Persistence** — `SaveManager` writes one versioned JSON per slot in `user://saves/`, with a cheap `meta` block for the slot list and 17 sections. In-flight jobs save as **type + targets** and restart their stage (`JobSerializer`); board jobs re-derive. Reservations are never saved — restored jobs re-claim through the normal path.

## Invariants

- Jobs must never destroy carried resources on cancel: leftovers stay on the pawn (swept by `Job_StoreInventory`) or become a `ResourcePile`.
- Job `cancel(as_failed)` releases the job's storage reservations; after any cancel path, `reserved_withdraw`/`reserved_deposit` must reconcile to zero. The `_ended` latch exists to guarantee this — any callback that can fire after a job ends must early-return on it before mutating state.
- Slot-holding components (sleep, recreation, shop, recharge, robot repair, medical) claim up front, release in the job's `_on_end`, and rebuild empty on load. This is why "all slots occupied" degrades gracefully instead of leaking.
- **Derived state is re-derived, never saved**: adjacency fields, INF-duration happiness modifiers, field-driven maluses. Only genuinely stateful things get save keys — and every new system ships its own section, backward-compatibly where it can.
- `EconomyManager.record_income` returns the **net** after the ARC levy skim; the caller must credit the station with that returned value, not the gross. (This was a real money-loop bug.)
- Placement pays only on success: `WorldManager.add_module` returns null on failure and `purchase_and_add_module` withdraws after. `overlap_module()` has side effects (truss removes itself), so placement can't be pre-validated twice.
- Balance numbers belong in `.tres` data or exported vars, not code constants.
- New job types declare a `JobBase.Category` **and** a `get_save_data()`/`JobSerializer` entry. New pure-logic rules get a GUT test.
- Tabs for indentation; `class_name` on every script; comments explain *why* (race avoidance, reservation semantics, coalescing rationale), matching the existing bar.
